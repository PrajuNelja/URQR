# URQR API Endpoints

This guide lists the backend's controller endpoints in a practical test order, from login and hotel setup through menu, billing, and reporting.

## Before you call an endpoint

- Local base URL: `http://localhost:8080`.
- Login and refresh endpoints do not need a bearer token. For protected endpoints, send `Authorization: Bearer <accessToken>`.
- Platform endpoints require a Platform Admin token. Hotel endpoints use the hotel ID embedded in the signed-in staff token, so do not send a hotel ID for regular hotel operations.
- Replace example IDs and credentials with values from your own responses. Passwords and token strings below are placeholders.
- JSON examples are representative request or response bodies. GET endpoints have no request body. Decimal prices and amounts use JSON numbers.
- Role access: Platform Admin manages hotel provisioning and adds Manager/Cashier accounts; a hotel Manager manages hotel settings, staff, roles, and menu; Manager and Cashier handle orders, payments, bills, and receipts; Manager, Cashier, Cook, and Waiter can read the menu.

New hotel IDs are generated without separators from the first three letters of the hotel name, the two-letter country code, the state or region code, and a four-digit sequence (for example, `GRAINTN0001`). The sequence increments for each name-prefix, country, and state combination. `countryCode` and `stateCode` are required when creating a hotel. Existing hotel IDs are preserved when the database is migrated.

## Common test flow

1. Sign in at `/api/v1/platform/auth/login` and copy the access token.
2. Create a hotel at `/api/v1/platform/hotels`, then save its hotel ID and initial Manager email.
3. Sign in at `/api/v1/auth/login` with the Manager credentials to get a hotel-scoped token.
4. Use the Manager token to create a category and menu item, then create an order and record payment if needed.
5. Use the returned order ID to request the bill and receipt. A receipt lookup can return 404 if no receipt was created for that order.

For interactive requests, open `http://localhost:8080/swagger-ui/index.html`. Paste an access token into Swagger's **Authorize** dialog; do not include the word `Bearer` if the dialog adds it automatically.
